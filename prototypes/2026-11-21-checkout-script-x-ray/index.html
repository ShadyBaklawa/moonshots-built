Harder to control

A Content-Security-Policy can allow or block a whole domain, but it can't inspect what a script does once it's allowed to run. These two categories need more than a CSP entry.

Inline scripts

Inline <script> blocks have no URL for a CSP to allow or block by domain. The only ways to control them are 'unsafe-inline' (which defeats most of the protection) or giving each block a per-deploy nonce or hash — both require a developer to change how the page is built.

    Tag-manager & dynamic loaders

    These vendors (tag managers, experimentation and analytics containers) fetch and run additional code after your page loads, on their own schedule. Allowing their domain in a CSP does not stop them from pulling in new, unreviewed scripts later — the 178-organisation incident started exactly this way.
